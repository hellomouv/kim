# ADR 0090: Kim Manager becomes a minimal three-icon launcher

- Status: accepted
- Date: 2026-11-14
- Issue: maintainer request 2026-11-14 ("Make All Three Tools Usable and Redesign Kim as an
  Ultra-Minimal Launcher"); supersedes the layout of DESIGN_SYSTEM §3.2 (two-pane catalog) and
  the Step 06 window of ADR 0014, keeps its backend (ADR 0013), builds on ADR 0089

## Context

Kim Manager looked like a software manager: a header with the catalog version, a channel box
and *Refresh catalog*, a 320-point tool list, and a details pane with tables, features,
permissions, entry points and install paths. The maintainer wants a tiny, beautiful home for
three tools: open Kim, click a tool, use it. The backend (signed catalog, explicit and
transactional installs, the local mirror of ADR 0089, shortcuts) works and stays.

## Decision

1. **The main view** is one seamless background with three tiles from the upper-left corner, in
   this order: Subak, Noeul, Ddalgak (`LAUNCHER_TOOLS`), and a painted gear anchored to the
   lower-right corner. One quiet status line (progress, results that fade after six seconds,
   errors until clicked) appears only while there is something to say. No header, sidebar,
   tabs, table or details pane. The window is 368 × 224 points (minimum 336 × 196) with the
   normal Windows frame; it grows to at least 580 × 460 while Settings or Information is open
   and returns to its size afterwards.
2. **Icons.** Subak uses its watermelon (ADR 0073). Noeul and Ddalgak get original icons in the
   same style (assets/noeul, assets/ddalgak; generated by `assets/brand/make_tool_icons.py`): a
   striped setting sun over a horizon (노을, the evening glow) and a mint keycap with click marks
   (딸깍, the sound of a click), on Subak's 40-unit tile. They are also linked into `noeul.exe`,
   `noeulw.exe`, `ddalgak.exe`, `ddalgak-gui.exe` and `ddalgak-editor.exe` (kim-winres).
3. **State from the inventory.** A tile is *installed* (full colour) only when Kim's install
   record is valid **and** the program the tile starts exists in the installed version's folder;
   a missing program is *needs repair* (grey, a warning mark; Repair reinstalls the same version,
   verified like any install). Not installed is grey (luminance) with a small download mark;
   not available (no release, or not for this PC) is grey and says why. An update shows an
   accent dot.
4. **Left-click**: an installed tool starts at once, without a question (Subak: `subak-gui.exe`;
   Noeul: `noeulw.exe`, the resident app; Ddalgak: `ddalgak-gui.exe` — the tray app, a single
   instance — then `ddalgak-editor.exe`). A tool in the notification area says so on the status
   line. Otherwise a small dialog asks first: what will be installed, from where (a local
   preview is called that), and what the tool may do on this computer (`KIM-SEC-006`); only its
   *Install* button installs (`KIM-SEC-001`). Kim never installs anything because it starts.
5. **Right-click** opens a compact menu with only what fits the state. Installed: the tool's
   programs, *Settings…* (Noeul: starts Noeul if needed and asks it to open its settings window;
   Ddalgak: the rule editor; Subak: disabled, it is configured in its file — the reason is the
   hover text), *Open installation folder* (Explorer), *Update to …* when one exists, *Check for
   updates* (reads the catalog again, never installs), *Uninstall…* (the existing confirmation,
   data kept unless explicitly purged), *Information*. Not installed: *Install…*, *Information*.
   Unavailable or busy entries are disabled with the reason.
6. **Settings** (the gear) has four short sections: *General* (theme System / Dark / Light,
   saved in `manager.json` next to Kim's `settings.json`; offline mode and update checks, Kim's
   settings; the channel), *Shortcuts* (Kim Manager's actions with **Change** — keyboard capture,
   `Esc` cancels, nothing fires while capturing, capture stops when the window loses focus —
   **Off** and **Reset**; they run `kim hotkeys set/disable/reset` next to the window, the same
   checks and file as the CLI; sequences and typed syntax stay on the CLI), *Catalog* (version,
   source, signer, expiry, *Refresh now*), *About*.
7. Unchanged: the CLI and headless contracts, the installer, the mirror rules (ADR 0089), the
   focus-only shortcuts (F1 list, F5 refresh, user bindings), no background process, no
   automatic install or update.

## Consequences

- Information that used to be on screen all the time (features, permissions, entry points,
  paths) is one right-click away; permissions are still shown before every install.
- `tool.install` / `tool.update` / `tool.uninstall` act on the tile last clicked or
  right-clicked (the first tool before any click).
- Tested: 17 headless UI tests (`crates/kim-manager/tests/ui.rs`: order, layout and resizing,
  install/launch, repair, menus, uninstall with data kept, settings persistence, shortcuts,
  display scales 150 % and 200 %, the local mirror), and on the real desktop with the release
  build (a sandboxed profile; screenshots in the session's scratchpad): launcher, menus,
  installing all three tools from the local mirror, launching each (Subak shell, Noeul F1
  overlay, Ddalgak tray and editor, Noeul's settings window), closing Kim with the tools
  running, reopening, Settings (theme, shortcut change, catalog refresh), uninstall refused
  while Subak ran, uninstall and reinstall with data kept, repair, resizing.
- Not tested on the real desktop: changing Windows display scaling (it would rescale the
  maintainer's whole desktop); covered by the headless scale test.
